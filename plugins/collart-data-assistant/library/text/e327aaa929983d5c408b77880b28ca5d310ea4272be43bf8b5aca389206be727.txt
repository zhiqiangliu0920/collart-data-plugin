# DAU 趋势、获客与留存诊断

来源：2026-04-20 基准文档、2026-05-14 两份平台期诊断脚本。2026-09-13 用户确认删除固定 DAU 阈值，仅保留诊断方法。以下为静态整理，没有重跑历史数据。

## 分解与比较

先看最近完整 30 天 DAU、新用户、老用户与新用户占比，再比较同一星期几的 90 天趋势，避免周内结构变化被误读为平台期。按国家、渠道拆分“新增规模 × D1 留存”；小样本单列，原脚本的 500/200 人门槛只是当时筛选，不能变成固定业务告警。

新增 cohort 按安装/首次识别日 × 用户键形成，回访按 cohort_date + N 精确关联。D30 只比较已经完整观察 30 天的 cohort；补出没有回访的零行。整体留存率用总回访 / 总 cohort，不把各天百分比简单平均当作总体率。

## 数据与口径检查

- 当前 DAU 从 [DAU 指标](../indicators/dau.md) 与 [公司 ADS 红线](../../1company/analysis_playbooks/collart_ads_redlines.md) 选源；新 active 表计活跃需 `is_active`，避免仅收入骨架行进入 DAU。
- 历史 DWD 脚本使用 `is_new` 布尔值；旧基准文档写 `'New'/'Old'`，两种表达不能混用。使用前以对应表定义确认。
- 两份诊断脚本混用 `geo.country` / `traffic_source.source` 嵌套字段与 DWD 扁平字段。方法可复用，旧脚本不作为已验证查询。
- 旧异常 SQL 把 `LAG` 放在 `WHERE` 中；修订示例先算窗口值再筛选。连续日期应先补日期轴，不能把跨日缺数当作日环比。
- 固定的 5–8 万正常值、4.5 万预警及其他 P0/P1/P2 数值已移除。当前预警阈值需要单独配置或业务确认。

趋势计算先核对每日唯一、日期完整以及新增与活跃口径一致，再计算 `LAG(dau, 1)`、`LAG(dau, 7)`，用 `SAFE_DIVIDE` 计算日环比和同星期几变化。配套 `dau_trend_diagnostics.sql` 已转存对应 Codex 项目；它接受日聚合参数，不内置生产表路由。
