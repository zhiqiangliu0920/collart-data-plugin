# 原始埋点与漏斗证据

## 事件入口

Android 与 Web/Fashion 的原始 GA4 来源为 `storytemplate-10a27.analytics_232977577.events_*`。Android 使用相应 `app_info.id`；Web 使用 `app_info.id IS NULL`，Fashion 还要按产品归属规则区分。

iOS/VidArt 使用 `vidart-8b8ca.analytics_528583115.events_*`，需按 bundle 与测试来源核对过滤。具体表是否存在及日期覆盖仍要检查。

## 测量边界

优先查 `ads_dim_metric_rule`，确定实际事件、参数和触发条件，再判断能否用 ADS 已配置指标。曝光、点击、服务创建、生成成功、支付发起、付款成功是不同阶段。相近名字不足以证明业务含义相同。

事件定义应来自真实 UI 动作与事件字典。缺少输入事件时不能直接测量“输入后放弃”；缺少服务端付款证据时不能把 checkout 当支付成功。

UV 只说明某步命中过，不自然构成按顺序完成的漏斗；严格漏斗还需要身份、顺序、会话或任务 ID、允许时间间隔、重复重试处理。未命中事件宽表的用户，分母需从完整 cohort / active 获取。

原始事件查询约束见 [SQL 规范](sql-practice.md)。
