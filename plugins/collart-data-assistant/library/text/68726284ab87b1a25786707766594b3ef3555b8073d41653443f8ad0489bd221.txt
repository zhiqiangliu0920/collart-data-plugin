## ⚠️ SQL 编写与执行核心红线（2026 Q2 强制执行）

### 1. BigQuery 执行红线
- **年份确认**：按任务指定日期确认年份；本文旧示例来自 2026 年，不能固定沿用。
- **30天跨度限制**：查询 `events*` 分片表时，日期跨度绝对不能超过 **30 天**。
- **强制分区过滤**：必须使用 `_TABLE_SUFFIX` 过滤日期范围，禁止仅使用 `event_date` 过滤。
- **Web端过滤**：查询 Web 端数据时，必须加上 `app_info.id IS NULL` 以排除干扰。

### 2. SQL 存储与命名规范
- **存储路径**: `{project}/reports/YYYY-MM-DD/{topic}/`（正式报告与配套证据）；可复用 SQL 放 `sql_presets/`，未完成草稿放 `sql-snippets/`
- **文件命名**: `{分析主题}_{日期}.sql` 或 `{分析主题}.md`
- **同步要求**: 必须同步至 OneDrive，确保异地办公可用性。

### 3. 查询类型区分
| 类型 | 定义 | 处理方式 |
|:---|:---|:---|
| **正式分析** | 完整的业务分析，需沉淀 | SQL 保存到知识库 + 告知位置 |
| **临时查询** | 快速数据查看，无需沉淀 | 只告知 SQL 路径/行号，不强制保存 |

### 4. 编写与优化技巧
- **宽表先行**：优先在 CTE 中使用 `UNNEST` 展平参数，避免主查询重复操作。
- **语法糖**：优先使用 `COUNTIF()` 替代 `COUNT(CASE WHEN...)`，使用 `GROUP BY ALL` 简化代码。
- **成本预估**：大表查询前先预估扫描量，不确定时先询问。
