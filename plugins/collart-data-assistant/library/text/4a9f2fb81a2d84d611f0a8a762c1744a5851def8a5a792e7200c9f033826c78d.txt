# `aidata2025.ads_collart.ads_oper_revenue_collart_fashion_di`

> **2026-09-09 已删除**。购买次数 / 累计收入改读 `ads_collartfashion.ads_oper_user_active_di` 或 daily `purchase_revenue`。Dataform `fashion_revenue.sqlx` 已删。

## 1. 基础信息

- 中文名：【停更】Collart Fashion 每日 Stripe 收入汇总
- 表类型：ADS 日汇总表（历史兼容）
- 行粒度：`event_date`
- 分区字段：`event_date`
- 更新频率：已停写
- 口径切换日期：2026-08-27；停写：2026-09-09
- 上游：旧用户日表（亦已停写）

## 2. 核心作用

- 为 Fashion 日报和核心指标表提供兼容的每日收入、交易笔数。
- 保留旧表字段，避免下游因用户粒度改造而中断。

## 3. 核心字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `event_date` | DATE | Stripe 收入日期 |
| `package_name` | STRING | 固定 `collart_fashion` |
| `revenue_usd` | FLOAT64 | 用户日明细收入之和 |
| `pay_cnt` | INT64 | 用户日明细交易笔数之和 |
| `etl_time` | TIMESTAMP | 入库时间 |

## 4. 口径与红线

- 2026-08-27 起不再从 GA4 URL、商品价格表或汇率估算收入。
- 每日值必须严格等于用户日收入表按 `event_date` 聚合结果。
- Fashion 用户归属、Stripe 过滤、未来 succeed 防回溯和内部用户排除规则，见 [用户日收入表](aidata2025.ads_collart.ads_oper_user_revenue_collart_fashion_di.md)。

## 6. 数据质量

- 表要求分区过滤。
- 2026-08-27 已回填 2026-06-01～2026-08-26，并与用户日明细、Fashion 核心指标表完成一致性校验。

## 7. 示例 SQL

```sql
SELECT
  event_date,
  revenue_usd,
  pay_cnt
FROM `aidata2025.ads_collart.ads_oper_revenue_collart_fashion_di`
WHERE event_date >= DATE_SUB(CURRENT_DATE('Asia/Shanghai'), INTERVAL 30 DAY)
ORDER BY event_date;
```
