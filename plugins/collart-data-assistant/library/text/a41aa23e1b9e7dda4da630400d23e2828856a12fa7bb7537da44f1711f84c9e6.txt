# 指标：Collart Web 新用户（user_pseudo_id 首次发现）

## 1. 背景与问题

Collart Web 用户身份有两层：

| 标识 | 说明 | 出现时机 |
|---|---|---|
| `user_pseudo_id` | GA4/Firebase 分配的匿名设备/浏览器 ID | 访客访问即有 |
| `user_id` | 业务账号 ID | 登录后才有 |

**已知问题：**

1. `user_id` ↔ `user_pseudo_id` 为 **多对多**（换设备、清 Cookie、多账号登录均会导致交叉映射）。
2. Web 画像 `ads_oper_user_profile_df` 一行一个设备：`user_id` 只是**最后一次登录**；该设备全部登录号在 `user_ids`。按登录 UUID 查：`'UUID' IN UNNEST(user_ids)`，不要 `WHERE user_id =`。
3. GA4 的 `first_visit` 事件存在漏报/延迟/跨域重置等情况，**不能**作为唯一新用户口径。
4. 数仓 `ads_oper_user_new_collartweb_di` 的上游 `is_new` 与 `first_visit` 存在耦合，分析落地页、渠道归因时可能产生偏差。

## 2. 推荐口径（2026-07 起）

> **新用户 = 某个 `user_pseudo_id` 在 Collart Web 埋点中首次被发现的日期。**

| 要素 | 定义 |
|---|---|
| 行粒度 | `user_pseudo_id` |
| 新用户日期 `new_user_date` | 该 `user_pseudo_id` 在 Web 埋点中 **任意事件** 的最早 `event_date`（北京时间自然日） |
| 首次发现时间 `first_seen_time` | 最早事件的 `event_time`（DWD 字段） |
| 首次落地页 `first_landing_page` | 该 `user_pseudo_id` **第一次** `page_view` 的 `page_location`（完整 URL） |
| 首次落地路径 `first_landing_path` | 从 `first_landing_page` 提取的 path，如 `/ai-fashion-video` |
| 项目过滤 | `app_info.id IS NULL`（仅 Collart Web） |

**明确不使用：**

- ❌ 单独以 `first_visit` 事件作为新用户判定
- ❌ 以 `user_id` 作为新用户主键（可作为补充映射，见下）

## 3. 数据源

| 用途 | 表 | 说明 |
|---|---|---|
| 新用户日期 / 首次时间 | `aidata2025.dwd.dwd_oper_user_event_di` | `package_name = 'collart_web'`，成本低，适合批量聚合 |
| 首次落地页 | `storytemplate-10a27.analytics_232977577.events_*` | 从 `event_params.page_location` 取；DWD 的 `event_page` 对 `page_view` **为空** |
| 渠道/设备补全 | 首次发现日当天的 DWD 或 `ads_oper_user_new_collartweb_di` | 取 `country/device/traffic_src_*` |

凭证：默认 **aidata2025**；查 GA4 表用全限定名。

## 4. user_id 映射规则

分析时需 **以 `user_pseudo_id` 为主键**，`user_id` 仅作补充：

```sql
-- 一个 pseudo 关联过的全部 user_id（登录/换号）
pseudo_to_users: ARRAY_AGG(DISTINCT user_id)

-- 一个 user_id 关联过的全部 pseudo（多设备）
user_to_pseudos: ARRAY_AGG(DISTINCT user_pseudo_id)
```

**注意：** 不要用 `user_id` 去重算 UV，也不要假设「一个 user_id = 一个新人」。

## 5. 新/老判断（分析窗口内）

```sql
-- 某日新用户
WHERE new_user_date = @target_date

-- 窗口内新用户
WHERE new_user_date BETWEEN @start_date AND @end_date

-- 窗口内老用户（当日前已在 Web 出现过）
WHERE new_user_date < @start_date
```

## 6. 与现有表的关系

| 表/事件 | 关系 |
|---|---|
| `ads_oper_user_new_collartweb_di` | 仍可用于快速关联渠道字段；**新用户日期以 pseudo 首次发现为准**，二者不一致时优先 pseudo 口径 |
| `first_visit` | 仅作对比/诊断，不作主口径 |
| `dwd_oper_user_collartweb_di.is_new` | 日活表内字段，来源上游；复杂归因场景改用本口径 |

## 7. 验证数据（2026-07-01 ~ 2026-07-20）

| 指标 | 数值 |
|---|---:|
| 首次发现 pseudo 数 | 30,788 |
| 有 `first_visit` 的 pseudo | 28,587 |
| 首次发现日与 first_visit 不一致或无 first_visit | 2,227（7.2%） |

标准实现见 [`../sql_presets/new_user_by_pseudo_id.sql`](../sql_presets/new_user_by_pseudo_id.sql)。

## 9. 典型场景

- 落地页新用户分析：按 `first_landing_path` 聚合 `new_user_date` 当日 UV
- 渠道 ROI：新用户 JOIN 首次发现日的 `traffic_src_*`
- 登录后行为：pseudo 口径定新老，再通过 `user_id` 映射看付费（需接受多对多）
