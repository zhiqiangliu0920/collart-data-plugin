# `aidata2025.ads_collartfashion.ads_oper_user_active_di`

## 1. 基础信息

- 中文名：Collart Fashion 用户日明细
- 粒度：`event_date × user_pseudo_id`
- 分区：`event_date`
- 上游：
  - `aidata2025.dm.dm_collart_web_user_event_di`
  - `aidata2025.ads_collartfashion.ads_oper_user_revenue_di`
- 收入映射：按 `event_date × user_id` 汇总订单表；`fashion_active_revenue_enrichment` 后置校准
- 更新：Dataform 日更，常规回刷近 30 日

## 2. 核心作用

- 提供 Fashion 用户日活、渠道、国家、设备、留存等用户级维度。
- 自 2026-08-27 起承接 Fashion Stripe 用户日收入，写入 `revenue.purchase_revenue`。
- 作为 `ads_oper_user_profile_df`、`ads_oper_basic_indicator_attr_di` 和事件指标表的上游。

## 3. 收入字段

- `revenue.purchase_revenue`：该 `user_id` 当日 Fashion Stripe 实收（含点数包）。
- `revenue.new_revenue` / `resub_revenue` / `credit_revenue`：按订单 `description_type` 拆桶。
- `subscription.purchase_cnt` / `is_credit_pack` / `credit_pack_cnt` / `credit_amount`：与订单表同口径；`is_purchase` 在埋点或 `purchase_cnt>0` 时为真。
- 同一 `event_date × user_id` 只落到一个 `user_pseudo_id`。
- 国家空值用 Stripe `country`，仍空则 `unknown`。

## 4. 行口径与红线

- 有 Fashion 活跃行为的行：`is_active = TRUE`。
- 收入日没有 Fashion 活跃行为时，优先使用该笔支付成功事件对应的 Fashion `user_pseudo_id`；维度允许读取收入日后 1 天的同 pseudo active 行，以兼容 GA4 与 Stripe 日期跨日。仍无同日行为则生成收入补充行，`is_active = FALSE`。
- 统计 DAU 必须使用 `COUNT(DISTINCT IF(is_active, user_pseudo_id, NULL))`，禁止直接数全表行或全表 pseudo。
- 收入补充行不计 DAU、留存、流失、回流和事件 UV/PV。
- `subscription.*` 仍是客户端埋点口径，不能因存在 Stripe 收入而改写为订阅成功。

## 5. 下游传播

`revenue.purchase_revenue` 按以下链路上卷：

`ads_oper_user_revenue_di` → `user_active_di` → `fashion_active_revenue_enrichment` → `attr` → `country` → `daily`

旧日收入表 `ads_oper_revenue_collart_fashion_di` 已删除，购买次数 / 累计收入直接 SUM(active) 或读 daily。

`user_profile_df.revenue.purchase_revenue_all` 和 `ltv.*` 也从本表累计；画像的活跃日期与活跃天数只读取 `is_active = TRUE` 行。

## 6. 数据质量

- 2026-07-11～2026-09-08：订单 / active / attr / country / daily 均为 $632.59；用户日 33 行字段 0 差异。
- 纯支付补行不计 DAU。Stripe 二字码（如 `ID`）可能与 GA4 国名并存。
