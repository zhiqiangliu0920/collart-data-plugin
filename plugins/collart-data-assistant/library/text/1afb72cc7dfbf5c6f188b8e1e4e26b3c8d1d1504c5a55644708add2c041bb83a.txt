# Subscription Purchase（四端）

> 文档整理：2026-09-12；业务状态：documented；复核：reviewed_static。原业务日期见正文，本次未重新查询生产数据。


生效日期：2026-08-24

## 定义

`purchase` 表示用户当天发生过订阅或购买点数包行为：

```sql
is_purchase = is_subscribe OR is_credit_pack
```

`purchase_uv` 是两类购买用户的去重并集。禁止用
`subscribe_uv + credit_pack_uv` 直接相加，因为同一用户当天可能同时发生两类行为。

## 推荐字段

四端数据集：

- `aidata2025.ads_collartandroid`
- `aidata2025.ads_collartios`
- `aidata2025.ads_collartweb`
- `aidata2025.ads_collartfashion`

用户日字段：

- `ads_oper_user_active_di.subscription.is_purchase`（BOOL）

聚合字段：

- `ads_oper_basic_indicator_attr_di.subscription.purchase_uv`
- `ads_oper_basic_indicator_country_di.subscription.purchase_uv` / `purchase_uv_1d`
- `ads_oper_basic_indicator_daily_di.subscription.purchase_uv` / `purchase_uv_1d`

`purchase_uv_1d` = 新用户当日购买并集。`daily_compare` 的 `vip_user_0` / `首日订阅转化率` 用该字段，不再用 `subscribe_uv_1d`。

## 端侧来源

- Android：订阅成功事件的 premium 商品，或点数包商品。
- iOS：Apple IAP 的 Auto-Renewable Subscription，或 Consumable。
- Web：Stripe 的 Subscription creation/update，或 credit。
- Fashion：`vip_subscribe_succeed` 或 `credit_pack_purchase` 事件。当前 Fashion
  原有 `is_subscribe` / `is_credit_pack` 未填充，`is_purchase` 直接按两类事件生成。

## 俄罗斯

俄罗斯主收银是 Stripe `dwd_cdct_revenue_stripe_di` 且 `currency='RUB'`，**不进** 客户端 `is_purchase` / `purchase_uv`。
App 端 `subscription.purchase_uv` 看起来会接近 0；用户粒度金额看 `ads_oper_user_active_di.revenue`（purchase/credit 已叠加 RUB），不要扫 `ods.orders`。
