# 新产品 GA4 数据摸底与上线诊断

适用：尚未确认事件覆盖、用户粒度和数据来源的新产品。来源：2026-05-14 的 Vibedance 探索脚本与诊断框架，以及 iOS 参数/权限探针。Vibedance 原数据源为 `vibedance-540a0.analytics_533044528.events_*`，属于独立产品，原文件放在 Android 下不代表 Collart Android 口径；本次未验证当前访问或业务状态。

## 1. 确认能看到什么

先查数据集权限、分表日期覆盖、事件名和参数类型，再限定完整日期窗口。凭证所属项目、创建查询任务的项目和被读取的数据集分别核对；访问失败不等于没有数据。`COUNT(*) ... LIMIT 1` 不是小扫描量保证。

原探索从 2026-01-01 开始且无上界，复用时应先收窄窗口。GA4 查询遵循 [全局 SQL 规范](../../0global/sql_standards/README.md)，明确后缀上下界、产品条件和用户键；event_date 的字符串与 DATE 运算先对齐类型。

## 2. 建立基础事实

- 列出完整窗口内事件 PV/UV、国家、设备和版本；session_start UV 与全事件 UV 分别呈现，正式 DAU 由产品定义确认。
- 首次用户以实际 first_open/first_visit 或经确认的首见来源建立 cohort。历史覆盖不足时，窗口内首次观察不等于首次使用。
- 留存按同一 cohort 与日期偏移计算；D7/D30 只比较观察期完整的人群。分组汇总用总人数计算，不简单平均每日比率。

## 3. 对齐实际流程

从实际产品步骤列出进入、上传/选择、提交、成功、展示、下载/分享，再逐项映射真实事件。步骤和事件尚未确认时记录缺失，不把假设事件名当作已上报。漏斗需要同一身份键、顺序、观察窗；同窗独立 UV 只能说明触达。

参数探查同时检查 string/int/double/float 类型，区分 key 缺失、事件不带值、类型选错和权限不足。旧 template/material/service/model 等参数只作候选，不当作当前业务字典。

## 4. 诊断变化

按版本、国家、渠道拆分新增、活跃、留存、失败和功能使用趋势；区分缺数、上报变化、投放变化与真实产品变化。比较同星期几、样本量和观察期，再形成待验证假设。

原框架的 DAU、留存、漏斗“合格线/优秀线”以及异常响应阈值均缺少产品依据，已从推荐方法移除。需要告警时单独确认依据、适用范围和响应方式，不把通用经验值变为业务规则。

## 5. 形成可复核结论

报告说明时间、产品、用户键、来源、观察覆盖、关键发现和证据缺口。报告与一次性 SQL 留在对应 Codex/Cursor 项目；稳定的事件定义、指标与分析经验再提炼回知识库。原框架的待填写报告壳与历史脚本不再作为正文维护入口。
