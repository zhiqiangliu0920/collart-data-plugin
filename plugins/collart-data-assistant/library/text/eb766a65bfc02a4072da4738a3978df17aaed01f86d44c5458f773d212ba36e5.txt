# Collart 大R准实时播报

## 1. 适用范围

- n8n 工作流：`Collart 大R准实时播报`
- 工作流 ID：`4miYGb3wT4Kbxtlx`
- 运行窗口：北京时间 **09:15–01:00**。01:00–09:14 不触发。
  09:15 首拍，之后每 6 分钟；0 点那一小时仍跑，01:00 停。
- 夜里 01:00–09:10 攒下的人，由 **`Collart 大R播报` 每天 09:10** 统一发，不在准实时里再打一张凌晨卡。
- **价值 / 国家 / 评分 / 调用次数 / is_r / 渠道 / 活跃日**：一律读 `big_r_user_value_state`。
- 手动触发不受此时段限制。

## 2. 累计价值

准实时累计价值统一读取 `big_r_user_value_state.lifetime_value`，与第 1 节及[状态表定义](../tables/aidata2025.ads_collart.big_r_user_value_state.md)一致。其来源是支付账本，包含确认与退款金额。

旧版“画像 ADS value + 当天收入”拼接法保留在整理前证据，不再作为此工作流当前公式，避免重复叠加。阈值、名单、发送和回调规则仍按本页原工作流说明；本次未修改或执行 n8n。

## 3. 候选规则

- Android / iOS：累计价值 `>= 50`。
- Web：累计价值 `>= 20`。
- 必须满足 `is_r = 0`。
- 活跃门槛（**满足任一即可**，2026-09-09）：
  - 画像 `last_active_date` 在近 14 天；或
  - 账本 `last_paid_at` 为北京**当天**（画像活跃停更、但当天付费跨线的人也能进）。
- **Web ≥100 首播例外（2026-08-20）**：若 `alert_log` 尚无记录，且北京**当日有付费**，
  即使画像已是 `is_r=1`（production 全量同步抢先打标），仍应进入候选并完成自动入表 + 播报。
  **不补历史 backlog**（非当日付费、且活跃也不在 14 天内的静默大R 不出候选）。去重仍靠 `alert_log`。
- 已存在于大R Google Sheet 或忽略 Sheet 的用户不再处理。

## 4. Web 播报与自动入表

- Web 从 50 档升到 100 档不重复播报；播报去重键固定为
  `app_name + user_id`，不按档位拆分。
- Web 首次被发现时已达到 `>= 100`：
  1. 自动写入大R Google Sheet；
  2. 调用 Cloud Run 同步线上库；
  3. 成功后发送播报卡片；
  4. 卡片中的“加入大R”显示为禁用态“已自动加入大R”。
- Web 已在 50 档播报、之后升到 `>= 100`：
  - 自动写入 Sheet 并同步 Cloud Run；
  - 不发送第二次播报。
- Web `50–<100`、Android、iOS 保留人工“加入大R”和“忽略”按钮。

## 5. 去重与失败重试

- 成功发送卡片后写入
  `aidata2025.ads_collart.big_r_realtime_alert_log`。
- 只有发送成功的用户才写播报日志；发送失败时下一轮重试。
- Web 自动入表路径按“大R Sheet → Cloud Run”顺序执行；任一步失败时，
  后续卡片发送不会执行。
- 空候选不发送卡片；单卡最多 20 人。
- 卡片 uid 链到 ai-viewer，窗口为报告日往前 **30** 天（T+1 日报同一口径）。

## 6. 画像表熔断

- 候选 SQL 执行前分别检查 Android、iOS、Web 高价值画像表。
- 任一画像表为空时使用 BigQuery `ASSERT` 终止本轮执行，不生成候选、不发送卡片。
- 该熔断用于防止 Android 表在 `DELETE` 与 `INSERT` 之间暂时为空时，
  将缺失画像错误地按 `is_r = 0` 处理。

## 7. 实时卡片回调

实时卡片 action value 带 `source=big_r_realtime` 和完整候选字段。
`飞书大R审核后自动写入` 工作流使用隔离分支直接消费这些字段；
原每日播报卡片和普通文本提单逻辑保持不变。
