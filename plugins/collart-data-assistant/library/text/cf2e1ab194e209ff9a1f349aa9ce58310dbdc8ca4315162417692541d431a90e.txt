## 2. 核心作用

1. 热漏斗列清单：`is_enabled AND is_materialized` → 必须出现在 `ads_oper_user_event_metric_di`（`*_pv`）以及 attr / country / daily 的同名 STRUCT（去掉 `_pv`）。
2. 冷指标口径：`is_materialized=FALSE` 时，数仓宽表没有该列；查数按本表规则扫 DM / `events_*`（Android 可 `CALL` 存储过程）。
3. 生成器输入：改 Sheet 后必须跑 `collart-event-metric-sync`（生成 SQLX → Dataform push → 回补），否则日刷宽表列不变。

## 3. 核心字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `app_name` | STRING | 仅合并表有；`collart_android` / `vidart_ios` / `collart_web` / `collart_fashion` |
| `metric_name` | STRING | 宽表列名，一律 `*_pv`；同一 `app_name` 内唯一 |
| `metric_chinese_name` | STRING | 中文名 |
| `event_name` | STRING | 事件表达式；Web `valid_user_pv` 为 `COMPOSITE` |
| `event_params` | STRING | 可空；`key = 'x'` / `in (...)` / `like '%x%'`，仅 AND |
| `agg_type` | STRING | `count_events` 或 `count_distinct_task_id` |
| `is_enabled` | BOOL | FALSE = 停用，不进宽表、不查 |
| `is_materialized` | BOOL | TRUE = 热指标进宽表；FALSE = 冷指标 |
| `sort_order` | INT64 | 列顺序 |

Sheet 格子必须是**纯文本**，不要当公式。`service_type` / `function_type` 独立列已并于 `event_params`。

## 4. 口径红线

表达式只允许：

```text
= 'Home_show'
in ('a','b')
like '%video%'
```

禁止任意 SQL / OR（Web `valid_user_pv` 除外，生成器特判）。  
参数 key 必须存在于 DM：`params_info`（Android/iOS）或 `web_params_info`（Web/Fashion）。比较前 `LOWER()`。

规则 → SQL：

| 规则 | 写进用户日宽表 |
|---|---|
| `metric_name` | 列名 `*_pv` |
| `event_name` + `event_params` | AND 拼条件 |
| `count_events` | `COUNTIF(条件)` |
| `count_distinct_task_id` | `COUNT(DISTINCT IF(条件, task_id, NULL))` |

attr / country / daily 列名 = `metric_name` 去掉 `_pv`，类型 `STRUCT<uv, pv>`（部分漏斗另有 `new_uv` 等切片，**不由 Sheet 驱动**）。

## 5. 关联表

| 表 | 关系 |
|---|---|
| `ads_oper_user_event_metric_di` | 热指标用户×日 `*_pv` |
| `ads_oper_event_metric_attr_di` | 热指标日×默认维 `STRUCT<uv,pv>` |
| `ads_oper_event_metric_country_di` | 热指标日×国家 |
| `ads_oper_basic_indicator_daily_di` | 日报事件 STRUCT；另有 DAU/留存/收入等非事件列 |
| DM `dm_collart_*_user_event_di` | 规则落地时的事件源 |
| GA4 `events_*` | DM 仍没有该事件时再下钻 |

## 6. 数据质量

- 改 Sheet **不会**自动改宽表。热指标必须走 skill / 生成器 + Dataform + 回补。
- `CREATE TABLE IF NOT EXISTS` 不会加新列，扩列必须 `ALTER TABLE ADD COLUMN`。
- daily 上的 `churn_uv` / `dnu_free` / `vip_dau` 等是经营指标，不是规则表事件列。
- 不要对合并外表 `INSERT` / 旧 seed / `CREATE OR REPLACE`。不要再重建各端 `ads_dim_metric_rule`。
