# Collart Android 数据血缘

## 整体数据流

```
GA4 events_* → DWD → DM dm_collart_android_user_event_di
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       active     user_event_metric    profile
                         │
                         ▼
              event_metric_attr / country → daily
```

事件列清单来自 Sheet 外表 `ads_dim_metric_rule`（生成器展开进 SQLX，调度不 JOIN 规则表）。
冷指标按规则扫 DM，或 `CALL sp_query_event_metric_by_tag`。

```
Firebase SDK
    │
    └──→ events_* (原始埋点)
            │
            ├──→ 用户行为分析
            │       └──→ 与 orders 关联（user_id）→ 付费分析
            │
            ├──→ 功能使用分析
            │       └──→ 与 user_properties 关联 → 用户画像
            │
            └──→ 留存分析
                    └──→ 自关联（user_pseudo_id + 日期）
```

## 表间关联关系

| 主表 | 关联表 | 关联字段 | 用途 | 示例 |
|------|--------|---------|------|------|
| events_* | orders | user_id | 行为+付费 | 用户行为与付费关联 |
| events_* | user_properties | user_pseudo_id | 用户画像 | 用户属性分析 |
| events_* | events_* | user_pseudo_id | 留存分析 | 自关联计算留存 |

## 常用 JOIN 模式

### 用户行为 + 付费
```sql
SELECT 
  e.user_id,
  e.event_name,
  o.revenue
FROM events_* e
LEFT JOIN orders o ON e.user_id = o.user_id
WHERE e.app_info.id = 'free.ai.photo.generator.collart.ai'
  AND e._TABLE_SUFFIX = '20260301';
```

### 用户画像分析
```sql
SELECT 
  e.user_pseudo_id,
  (
    SELECT up.value.string_value
    FROM UNNEST(user_properties) up
    WHERE up.key = 'country'
  ) as country,
  COUNT(*) as event_count
FROM events_* e
WHERE e.app_info.id = 'free.ai.photo.generator.collart.ai'
GROUP BY e.user_pseudo_id, country;
```

### 留存分析
```sql
WITH first_visit AS (
  SELECT user_pseudo_id, MIN(event_date) as first_date
  FROM events_*
  WHERE app_info.id = 'free.ai.photo.generator.collart.ai'
  GROUP BY user_pseudo_id
),
retention AS (
  SELECT 
    f.first_date,
    DATE_DIFF(e.event_date, f.first_date, DAY) as day_diff,
    COUNT(DISTINCT e.user_pseudo_id) as retained_users
  FROM first_visit f
  JOIN events_* e ON f.user_pseudo_id = e.user_pseudo_id
  WHERE e.app_info.id = 'free.ai.photo.generator.collart.ai'
  GROUP BY f.first_date, day_diff
)
SELECT * FROM retention;
```

## ADS 渠道两层血缘（2026-08-11 生效）

Android ADS 中，凡物理表暴露 `traffic_src_type`，必须同时暴露 `traffic_src_platform`，与 iOS/Web/Fashion 保持同构：

`dm_collart_android_user_event_di` → `ads_oper_user_active_di` → `ads_oper_user_profile_df` / `ads_oper_basic_indicator_attr_di` / `ads_oper_event_metric_attr_di`

- `traffic_src_type`：渠道性质（`delivery` / `inhouse` / `kol` / `nature`）。
- `traffic_src_platform`：具体投放平台（`ga_delivery` / `fb_delivery` / `x_delivery` / `tt_delivery` / `other_delivery`；非投放沿用渠道性质）。Instagram 属于 Meta，一律 `fb_delivery`。`sptt-` / `tt_official` 是 kol，不是 `tt_delivery`。
- profile 顶层渠道取首个非空渠道；若历史存在 `delivery`，改取首个 delivery；type/name/platform 必须同源同行。
