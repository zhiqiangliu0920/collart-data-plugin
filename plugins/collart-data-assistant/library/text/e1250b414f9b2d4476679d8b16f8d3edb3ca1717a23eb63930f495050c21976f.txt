# 指标：事件漏斗（规则表驱动）

## 1. 定义

四端事件漏斗（首页/生成/保存/功能位等）以 `aidata2025.ads_collart.ads_dim_metric_rule` 为口径源，用 `app_name` 区分端。

- **热指标**：`is_materialized=TRUE` → 读 ADS 宽表，不要现算。
- **冷指标**：规则在、宽表无列 → 按 `event_name` + `event_params` + `agg_type` 扫 DM；Android 可 CALL `sp_query_event_metric_by_tag`。
- **未登记**：先探 `events_*`，确认后写入 Sheet。

## 2. 推荐表

| 场景 | 表 |
|---|---|
| 用户日次数 | `{dataset}.ads_oper_user_event_metric_di` |
| 渠道/新老/VIP | `{dataset}.ads_oper_event_metric_attr_di` |
| 国家 | `{dataset}.ads_oper_event_metric_country_di` |
| 日报 | `{dataset}.ads_oper_basic_indicator_daily_di` |
| 规则 / 冷口径 | `aidata2025.ads_collart.ads_dim_metric_rule`（`app_name` 过滤） |

宽表 dataset：`ads_collartandroid` / `ads_collartios` / `ads_collartweb` / `ads_collartfashion`。各端规则表已删。

## 3. 口径冲突

- `subscription.*` 是埋点订阅，不是本规则表。
- daily 的 `churn_uv` / `vip_dau` 等不是事件规则列。
- 同名 `generate_start` 四端 event_name / agg 不同，按各端 Sheet，不要互抄。

详见 [playbook](../analysis_playbooks/event_metric_from_rule.md)。
