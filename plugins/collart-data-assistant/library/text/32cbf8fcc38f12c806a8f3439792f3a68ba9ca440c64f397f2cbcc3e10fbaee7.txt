# Collart Fashion Video 漏斗分析 Playbook

> 事件字典：[`../product/fashion_tracking_events.md`](../product/fashion_tracking_events.md)  
> 适用数据：`storytemplate-10a27.analytics_232977577.events_*`  
> 最后核对：2026-08-18

## 1. 默认范围

- Web 原始事件：`app_info.id IS NULL`。
- Fashion 用户：按 [`fashion_vs_main_site_user.md`](../indicators/fashion_vs_main_site_user.md) 判定；加工表优先使用 `package_name = 'collart_fashion'`。
- 服务链路必须限制 `service_type = 'fashion_video'`，避免混入 `ai_model` 和 Collart Web 其它生成服务。
- 付费链路优先限制 `from = 'fashion_video'`；`credit_pack_purchase` 当前源表未定义 `from`，需与用户/会话或订单做补充关联。
- 默认排除内部用户，规则见 [`internal_user_filter.md`](internal_user_filter.md)。

## 2. 漏斗分层

| 层级 | 推荐事件 | 完成定义 |
|---|---|---|
| Landing | `fashion_welcome_page_show` | 进入 Fashion 承接页 |
| Welcome CTA | `fashion_welcome_action_click` | 点击/触发承接页行动按钮；中文名与事件名有语义冲突，先验数 |
| Inspirations | `fashion_inspiration_show` → `fashion_inspiration_template_click` / `fashion_inspiration_template_recreate` | 浏览并进入模板生成 |
| Step 1 参考视频 | `fashion_reference_video_show` → `fashion_reference_video_link_success` 或 `fashion_upload_video_success` | 完成自定义参考视频输入；预设模板选择当前缺独立事件 |
| Step 2 模特 | `fashion_model_category_show` → `fashion_model_preset_click` / `fashion_model_history_click` / `fashion_model_upload_success` → `fashion_model_next` | 选定模特并进入下一步 |
| Step 3 服装 | `fashion_outfit_add_click` / `fashion_outfit_confirm` / `fashion_outfit_link_notify` → `fashion_outfit_next` | 配置 Outfit 并进入输出设置 |
| Step 4 生成意图 | `fashion_video_generate_click` | 点击 Generate Video |
| 服务启动 | `ai_service_start` | `service_type = 'fashion_video'` |
| 服务执行 | `ai_service_execute_start` → `ai_service_execute_success` / `ai_service_execute_failed` | 推理任务完成或失败 |
| 服务结果 | `ai_service_success` / `ai_service_failed` | 生成服务最终状态 |
| 结果消费 | `ai_result_download` | 下载生成结果 |
| 订阅 | `vip_show` → `vip_subscribe` → `vip_subscribe_succeed` | `from = 'fashion_video'` |
| 点数包 | `credit_pack_purchase` | 点数包购买行为；是否支付成功需和订单口径核对 |

## 3. 推荐转化率

| 指标 | 分子 | 分母 | 说明 |
|---|---|---|---|
| Welcome CTA 率 | CTA 去重用户 | Welcome 展示去重用户 | `fashion_welcome_action_click / fashion_welcome_page_show` |
| 模特完成率 | `fashion_model_next` 去重会话 | Step 1 已完成或 Generator 进入会话 | 预设参考视频缺选择事件，分母需保留两套口径 |
| 服装完成率 | `fashion_outfit_next` 去重会话 | `fashion_model_next` 去重会话 | 同会话且严格时间顺序 |
| Generate 转化率 | `fashion_video_generate_click` 去重会话 | `fashion_outfit_next` 去重会话 | Step 4 没有独立曝光事件 |
| 服务启动率 | `ai_service_start` 任务/会话 | Generate 点击任务/会话 | 先确认是否有稳定 task id；没有时用用户+时间窗口 |
| 生成成功率 | `ai_service_success` 任务数 | `ai_service_start` 任务数 | 不要用点击数直接当服务成功率分母 |
| 下载率 | 下载用户/任务 | 生成成功用户/任务 | `ai_result_download / ai_service_success` |
| 订阅点击率 | `vip_subscribe` 用户 | `vip_show` 用户 | 限定 `from = 'fashion_video'` |
| 订阅成功率 | `vip_subscribe_succeed` 用户 | `vip_subscribe` 用户 | 收入仍以订单成功状态为准 |

同一报告必须明确使用“事件次数、任务数、会话数或去重用户数”中的哪一种口径，不得混用。

## 4. 顺序与窗口

1. 事件按 `event_timestamp` 排序，用户主键默认 `user_pseudo_id`。
2. 交互漏斗优先按 `ga_session_id` 串联；需要跨会话时另建 24 小时或自然日窗口，并在标题注明。
3. 严格漏斗要求后一步时间晚于前一步；宽口径漏斗可只要求同一用户在窗口内出现，但必须单独展示。
4. 服务事件若存在任务 id，应以任务 id 作为 Generate → Start → Success/Failed → Download 主连接键；没有任务 id 时，不要把同一用户的并行生成误串成一条任务。
5. GA4 参数类型可能落在 `string_value`、`int_value` 或 `double_value`，提取时按字段实际分布验数，不凭字段名假设类型。

## 5. Generate 点击的核心切片

| 参数 | 分析用途 | QA |
|---|---|---|
| `model_source` | upload / preset 模特来源 | 检查是否覆盖 history，若没有需结合选择事件 |
| `template_id` | 参考视频/模板表现 | 检查空值与模板 Recreate 链路 |
| `model_preset_id` | 预设模特表现 | 仅 preset 模特预期非空 |
| `outfit_preset_id` | 服装预设或来源 | 源表未定义枚举，先验数 |
| `outfit_count` | 多 Outfit 复杂度 | 检查 1–5 以及模板要求的一致性 |
| `resolution` | 输出分辨率偏好与成功率 | 当前 UI 为 480P/720P/1080P，枚举可能动态变化 |
| `bgm_enabled` | 背景音乐开关 | 统一布尔值格式 |
| `has_prompt` | 是否使用提示词微调 | 不读取 prompt 原文做常规分析 |
| `video_model` | 生成模型表现、成本、成功率 | 动态枚举，不硬编码 |
| `has_scene` | 是否上传自定义场景 | 统一布尔值格式 |

## 6. 埋点验收清单

- [ ] 当前四步均能触发 `fashion_generator_show`，并检查 `step` 是否实际出现 4。
- [ ] 预设参考视频选择是否有可识别的事件；不能用曝光代替点击。
- [ ] 视频链接 confirm/success 能串联，且失败场景是否有事件。
- [ ] `fashion_model_category_show.type` 覆盖 preset/history/upload。
- [ ] `fashion_outfit_confirm.outfit_type` 实际枚举是 `preset_id` 还是源表原文 `presrt_id`。
- [ ] 商品链接导入是否记录平台、confirm、success/fail；当前仅有 notify。
- [ ] Generate 点击 10 个参数的覆盖率、类型和枚举通过验数。
- [ ] `ai_service_*` 均带正确 `service_type`，Success/Failed 可以互斥归因。
- [ ] 失败事件是否带 error code/reason；若无，补公共参数或服务日志关联。
- [ ] `vip_*` 的 `from = 'fashion_video'` 覆盖完整；点数包与订单成功状态可核对。
- [ ] `fashion_aesset_click` 是否仍未触发；若业务使用，需要先解决事件名与触发问题。

## 7. 不可直接推断

- `fashion_video_generate_click` 是生成意图，不等于任务已启动或生成成功。
- `ai_service_success` 是服务成功，不等于用户下载、发布、带来 GMV 或收入。
- `credit_pack_purchase` 的事件名不自动等价于支付成功，经营收入以成功订单口径为准。
- 官网展示的 ROAS、GMV、成本节省属于营销口径，不与数仓实际指标混用。
