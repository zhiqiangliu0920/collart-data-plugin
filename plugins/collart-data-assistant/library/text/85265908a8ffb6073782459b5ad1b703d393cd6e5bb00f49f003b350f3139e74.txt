# 团队数据知识库

2026-09-12 首版；仅供公司内部共享。本目录同时是一份可独立阅读的知识库和可安装的 Codex Skill。

设计：**公司私有 Git 仓库保存统一版本，Markdown 保存知识，Skill 帮助 Codex 按需检索和维护。** 同事同步仓库后读到同一套定义；数据库权限由公司单独授予。

## 已具备的内容

入口：[知识索引](knowledge/INDEX.md) · [Skill](SKILL.md) · [维护规范](references/maintenance.md) · [变更记录](CHANGELOG.md)。

- 四端项目标识、ADS 选表、数据血缘与原始埋点入口。
- 活跃与新增、留存、订阅与实际付费、收入重复计算风险。
- Web 设备与登录身份、渠道归因、Fashion 与主站的范围边界。
- SQL 使用约束、分析方法，以及旧资料冲突清单。
- 本地全文搜索、索引生成、草稿创建、结构检查和来源变化检查。

首批条目从现有资料整理，状态为 `documented` 或 `draft`；本次未查生产库，`verified_at` 保留为空。它们不是现网全量审计结果。历史资料里涉及表为空、断档、固定为零等状态，使用前需重查。

## 知识如何动态维护

```mermaid
flowchart LR
    A[业务说明 / SQL / schema / 分析验证] --> B[新增或更新知识条目]
    B --> C[记录来源与适用范围]
    C --> D[自动检查 + 必要核验]
    D --> E[合并到公司私有仓库]
    E --> F[同事同步版本]
    F --> G[Codex 按需引用]
    G --> B
```

这里的“动态”是可持续更新、检查和同步，不表示已经部署后台自动抓取。脚本不会擅自连接数据库、推送仓库或发送通知。

每次有新表、指标口径变更、埋点上线、业务规则变更或经过验证的数据坑，就更新对应条目。分析结论需提炼成可复用知识，并保留验证窗口；不能把某周“收入偏低”变成长期业务规律。

## 同事如何安装

将整个 `team-data-knowledge/` 目录同步到本机固定位置。建议将本目录单独放入公司私有 Git 仓库，或放在团队已有仓库；不要把作者的整个原始知识库连同个人配置一起分发。

Codex 当前支持用户级 `$HOME/.agents/skills`、仓库级 `.agents/skills`，并支持链接到 Skill 目录。以下使用用户级路径；安装规则核对于 2026-09-12，依据 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

Windows PowerShell，在本目录中执行：

```powershell
$teamSkillSource = (Resolve-Path -LiteralPath '.').Path
if (-not (Test-Path -LiteralPath (Join-Path $teamSkillSource 'SKILL.md'))) {
    throw '请先进入 team-data-knowledge 目录'
}
$teamSkillParent = Join-Path $HOME '.agents/skills'
$teamSkillTarget = Join-Path $teamSkillParent 'team-data-knowledge'
New-Item -ItemType Directory -Path $teamSkillParent -Force | Out-Null
if (Test-Path -LiteralPath $teamSkillTarget) {
    throw '目标已存在，请先核对现有安装，不自动覆盖'
}
New-Item -ItemType Junction -Path $teamSkillTarget -Target $teamSkillSource
```

macOS / Linux，在本目录中执行：

```sh
test -f SKILL.md || exit 1
mkdir -p "$HOME/.agents/skills"
test ! -e "$HOME/.agents/skills/team-data-knowledge" || exit 1
ln -s "$PWD" "$HOME/.agents/skills/team-data-knowledge"
```

新建 Codex 对话，选择 `team-data-knowledge` 或使用 `$team-data-knowledge` 调用。若没有显示，重启 Codex。当前机器上已有的 `shared-knowledge` / `collart-biz-analysis` 可以保留；初次试用显式指定本 Skill，遇到口径冲突按来源核实。

无需链接时，也可以把整个目录复制到用户或项目的 `.agents/skills/team-data-knowledge`；这种方式以后需要重新同步内容。

## 常用命令

在本目录执行：

```sh
python scripts/kb.py search "付费" --project collart_web
python scripts/kb.py search "user_ids"
python scripts/kb.py new --id trial-conversion --project example_project --kind metric --title "试用转正率"
python scripts/kb.py index
python scripts/kb.py check
```

`new` 创建草稿，不覆盖已有 ID；示例项目仅在运行命令后创建。`search` 每次读取实际文件，不依赖旧索引。`check` 返回结构错误、候选条目及过期复核提醒；`--strict` 可让提醒也返回非零退出码。新条目和重大修订的核验要求见维护规范。

维护脚本修改后，可运行 `python -m unittest discover -s tests -v` 做隔离验证。仓库中的 `.gitattributes` 固定文本为 LF，避免不同系统的 Git 换行转换改变知识与摘录哈希。

持有原始 `ai-knowledge` 资料的维护者可执行：

```sh
python scripts/kb.py source-check --source-root "/path/to/ai-knowledge"
```

该命令只比较来源文件哈希，报告缺失或变化及受影响条目。哈希一致不证明内容正确；正文换行改变也可能触发复核。同事仅持有此包时可以读包内来源摘录，不需要原始资料根目录。

## 团队运行建议

推荐由一名维护者管理共享版本，各项目指定业务或数据口径负责人。同事可以直接提交新条目或修订；涉及口径变化时请负责人核对证据和生效时间。负责人尚未指定的条目使用 `owner: null`。

有私有远程仓库后，贡献者提交变更供审阅，使用者在工作区干净时运行 `git pull --ff-only` 同步。出现冲突时先合并本地工作；不要强制覆盖同事改动。发布和同步后保留提交号，分析报告可引用该版本。

首批迁入后，本包中条目是团队版的维护正文；旧资料是有版本的来源素材，不再自动回灌全文。`source-check` 用于提醒可能遗漏的变更。团队决定全量迁移时，再逐项目明确原文档的替代关系。

## 首版边界与扩展

首版覆盖当前工作区已有的 Collart 四端知识，不等于公司所有项目已完整接入。产品用户场景、功能流程、商业模式、事件字典、表字段、指标契约、血缘、SQL 和问题处理均可按同一结构添加。下一批优先补各项目负责人、完整表字典、事件字典、正式指标验证和质量复核。

本次产物是可分发的本地版本：未创建公司远程仓库、未推送、未给同事发送安装包、未改任何人的 Codex 配置。正式共享前需要确定公司仓库位置及访问成员。
