# 知识库维护约定

## 维护边界

公司与四端顶层目录保留。表定义放 tables，产品/事件放 product，指标放 indicators，分析方法放 analysis_playbooks，加工关系放 lineage，可复用查询放 sql_presets。只按实际内容建目录，共用定义维护一处，项目保留范围和差异。

用户于 2026-09-13 确认：SQL 草稿、一次性脚本、分析报告及结果放对应 Codex/Cursor 项目，知识库不维护 sql-snippets 或 reports。从项目产物提炼长期规则，不复制整份报告；位置见 [PATHS](PATHS.md)。

## 正文与状态

当前可用结论和适用条件放在前面，历史差异注明原日期。每份正文说明用途、范围、来源和限制；不强制空章节，不重复大段整理说明。

收录、业务有效性与复核分别记录。已废弃表不作为默认来源；历史字段字典不等于当前 schema。没有依据的阈值、缺失事件、冲突口径保留问题边界，不能转写成确定业务事实。文档整理、用户确认、业务生效和生产验证日期不混用。

## 标识与恢复

knowledge_registry.json 保留持久标识、旧路径别名、合并和外部去向。纯迁移核对 SHA-256；正文变化保留差异与原审阅记录，重新静态复核，不沿用旧正文的哈希批准。

原件与审阅回执放在知识输入之外：

- [catalog/history 内容整理](../../ai-project/collart-agent-skills/history/2026-09-13/content-curation/README.md)
- [SQL 草稿与报告转存](../../ai-project/collart-agent-skills/history/2026-09-13/artifact-relocation/README.md)
- [本轮逐项优化](../../ai-project/collart-agent-skills/history/2026-09-13/knowledge-optimization/README.md)

catalog 生成器仅向外部维护证据目录输出；项目 README 是人工维护入口。备份、插件、安装缓存和项目产物不反向作为知识输入。
