# 指标：Fashion 新用户

> 文档整理：2026-09-12；业务状态：uncertain；复核：needs_review。原业务日期见正文，本次未重新查询生产数据。


## 1. 业务定义

**Fashion 新用户**：在 `event_date` 当日首次访问 Collart Web，且该新访归属 **Fashion 产品线**（非主站）。

| 要素 | 口径 |
|---|---|
| **推荐数据源** | `aidata2025.ads_collart.ads_oper_user_new_collartweb_di` |
| **Fashion 过滤** | `package_name = 'collart_fashion'` |
| **主键** | `user_pseudo_id`（行粒度：每自然日每个 pseudo 一行，`is_new=true` 上游过滤） |
| **cohort 日** | `event_date` |

> **红线**：Fashion 项目统计「新用户 / 新客 cohort」时，**优先用本表 + `package_name`**，不要用 `events_*` 里 `first_visit` + `page_location` 手工拼（成本高、与数仓产品线不一致）。

## 2. 与主站新用户的区别

| 站点 | 表 | 过滤 |
|---|---|---|
| Collart Web 主站 | 同表 | `package_name = 'collartweb'` |
| Collart Fashion | 同表 | `package_name = 'collart_fashion'` |

同一 `user_pseudo_id` 在 DWD 按 **当日首访产品线** 写入 `package_name`；用户在主站与 Fashion 各「新访一次」时，可能在不同日期、不同 package 各出现一行（少见，需专项分析）。

## 3. 关联 orders / 付费

1. 从 cohort 取 `user_id`；若 ADS 行内为空，可用同日 `dwd_oper_user_collartweb_di`（同 `package_name`）补全。
2. 关联 `aidata2025.ods.orders`：`orders.user_id = cohort.user_id`。
3. **成功付费**：`status IN ('active','paid','active_ending')`（见 [orders 表定义](../tables/aidata2025.ods.orders.md)）。
4. **排查支付链路**（含失败）：可不加 status 过滤，交付须标注「宽口径」。

## 4. SQL 模板

```sql
-- Fashion 新用户 cohort（单日或多日）
SELECT
  event_date AS cohort_date,
  user_pseudo_id,
  NULLIF(user_id, '') AS user_id,
  country,
  traffic_src_name,
  traffic_src_source,
  traffic_src_type,
  device_category
FROM `aidata2025.ads_collart.ads_oper_user_new_collartweb_di`
WHERE event_date BETWEEN @start_date AND @end_date
  AND package_name = 'collart_fashion';
```

可复用 preset：[`../sql_presets/fashion_new_user_orders.sql`](../analysis_playbooks/cohort_dashboard_analysis.md)

## 5. 弃用 / 慎用口径

| 口径 | 问题 |
|---|---|
| `events_*` + `first_visit` + `page_location` 含 studio/fashion | 与数仓 `package_name` 不一致；扫描 events 成本高 |
| 仅 `page_location` 含 `ai-fashion-video` | 过窄，漏掉 `/studio` 等 Fashion 入口 |

历史报告若用旧口径，须标注并在复盘中用本指标重算。
