# Fashion 收入

## 推荐口径（2026-08-27 起）

Fashion 收入以 Stripe 为金额真值，`vip_subscribe_succeed` 仅用于用户归属。

### 用户归属

1. `ads_collartfashion.ads_oper_user_event_metric_di.vip_subscribe_succeed_pv > 0`。
2. 通过同日 `event_date + user_pseudo_id` 关联 `ads_oper_user_active_di` 得到 `user_id`。
3. 取用户首次可映射 succeed 日期。
4. Stripe 付款日期必须不早于首次 succeed 日期，禁止未来事件回溯历史收入。
5. 排除内部用户。

### 收入和交易

- 源表：`pubdata2025.dwd.dwd_cdct_revenue_stripe_di`
- 过滤：`app_name = 'collart_web' AND revneue > 0 AND user_id IS NOT NULL`
- 去重：`transaction_id`
- 用户日收入：`SUM(revneue)`
- 用户日交易：去重后 `COUNT(*)`

### 推荐查询表（2026-09-09 起）

- 订单明细：`aidata2025.ads_collartfashion.ads_oper_user_revenue_di`
- 用户日：`ads_collartfashion.ads_oper_user_active_di`（`revenue.*` + `subscription.purchase_cnt` / `credit_*`）
- 上卷：attr / country / daily 的 `purchase_revenue`、`credit_revenue`
- 旧用户日表已停写；旧日收入表已删除，不要再用来统计购买次数或累计收入

### ADS 传播（2026-09-09）

订单表按 `event_date × user_id` 汇总进 active，再 attr → country → daily。  
无活跃支付日补 `is_active=FALSE` 行。DAU 必须滤 `is_active`。  
country 空值：Stripe country，再不行 `unknown`。

## 历史口径（不再推荐）

旧模型直接读取 GA4 `vip_subscribe_succeed`，从成功页 URL 提取金额、币种或以商品价格表估算收入。该逻辑只反映埋点且存在漏报、重复、金额估算问题，自 2026-08-27 起停用。

## 注意

- `vip_subscribe_succeed_pv > 0` 但无法映射登录 `user_id` 的 pseudo-day，不能和 Stripe 可靠关联，不计收入。
- 历史曾 succeed 的用户，只有 succeed 当日及之后的 Stripe 收入归属 Fashion。
- 不要把 Stripe 全站收入直接当 Fashion 收入。
