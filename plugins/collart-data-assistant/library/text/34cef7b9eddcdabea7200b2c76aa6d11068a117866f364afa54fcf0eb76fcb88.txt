# 分析方法论 Playbook

选题命中时按对应流程走。

---

## 1. 周复盘（WoW）

**目标**：一周经营变化 + 驱动拆解 + 风险行动项。

步骤：
1. 拉本周 vs 上周核心指标（DAU/DNU/留存/收入/ARPU/渠道/国家），用 daily+country。
2. 用固定 `sort_id` + `metric_name` 矩阵排版，四端可共用同一行序。
3. 量价拆解：DAU 变化 vs ARPU 变化，分清「量跌价升」还是「量价齐跌」。
4. 归因到国家/渠道：谁拖累、谁托底。
5. 输出结论 / 进展 / 风险 / 行动项。

日期窗口（T+1 体系）：昨日 T-1；7 日均取 **T-8 ~ T-2**；收入类 T-2（先 `DATE_ADD(event_date, INTERVAL 1 DAY)` 对齐）。

## 2. 增长诊断（DAU/新增异常）

排查顺序（由粗到细）：
1. **聚合表**看总量趋势（daily）。
2. **国家**拆解（country）：哪个市场变动最大。
3. **渠道**拆解（attr `traffic_src_type/platform`）：投放缩量 vs 自然量。
4. **新老结构**：新增掉还是留存掉；看 retain.d2 / rolling_retain。
5. **漏斗**：曝光→点击→生成→成功→付费，定位断点（event_metric）。

参考「六周驱动」模式：对每个下滑指标做国家级拆解，对比历史最好周期。

## 3. 收入作战台（4000/8000 目标）

结构（Android 8000 / Web 4000）：
1. **baseline**：当前 vs 目标缺口，ARPDAU × DAU 敏感性。
2. **P0 国家诊断**：按国对比历史最好周期，拆 delivery / 广告 / IAP。
3. **watchlist → guardrail → actions**：读数顺序固定，先看监控项，再看护栏，再定行动。
4. **完成标准**：7 日均 + 广告/IAP 双口径，防单日 spike 误判。

结构杠杆经验：零收入 paid traffic 治理、订阅失败转点数包、高 ARPU 老用户运营。

## 4. 新品/新功能诊断

框架（vibedance 模式）：
1. DAU / 新增趋势是否健康。
2. 核心功能漏斗每步转化。
3. 与老功能/老产品对比渗透率。
4. 异常项（区域 timeout、埋点缺失）排除后再下结论。

## 5. 单用户行为

- 画像看 `ads_oper_user_profile_df`；行为明细回 active / user_event_metric。
- Web 历史新增名单不全时说明限制。
- 敏感信息最小化。

## 6. 投放效果 / ROAS

- delivery cohort 按首日/多日 ROAS；标注是否有完整 D180。
- 内部用户不计入。
- DeepClick/ASA 按 [channels-attribution.md](channels-attribution.md) 分层，不混算。
- 结论区分「拉量」与「拉质」：新增涨但绑定/AI 启动/付费率低要点名。

## 报告结构模板

```
## 结论（1-3 句）
## 关键指标（表：本期 vs 上期 / 目标）
## 驱动拆解（国家 / 渠道 / 新老 / 漏斗）
## 风险与异常
## 行动项（可执行、带负责人视角）
## 口径与数据说明（覆盖窗、T+1、已知差异）
```

业务向：突出结论与行动，指标表精简，口径说明一两句。
数据向：附 SQL、全限定表名、覆盖窗与红线。
