# ai-knowledge 持续维护

> **三 Agent 共用权威正文**（Cursor / Codex / OpenClaw）。  
> 读知识库前可先读 `0global/PATHS.md`、`0global/AGENTS-SHARED.md`；Cursor 另有 `shared-knowledge` skill 侧重查询侧。

## 触发场景

用户口述任一信息时立即走本 skill：

- 「这个表是干啥的 / 用来算 XX」
- 「`status=active` 才算付费」
- 「新表 / 字段含义 / 上游来源 / 关联方式」
- 「把这个口径记到知识库」
- 任何需要**沉淀表、指标、口径、血缘**的口述

## 执行前（30 秒）

1. 读路径常量：`{KNOWLEDGE_ROOT}/0global/PATHS.md`
2. 查是否已有文档：在 `{project}/tables/` 与 `_generated/table_docs_20260521/tables/` 搜索表名
3. 若用户只给表名、未说项目：按 [routing.md](routing.md) 推断项目；不确定时先问一句

**禁止**：写入 `~/.cursor/`、`~/.codex/`、`~/.openclaw/`；禁止在 Markdown 中写密钥。

## 核心流程：用户说一个表 → 我知道写哪

```text
用户口述表信息
    │
    ├─ 1. 解析表名（全限定名优先）
    ├─ 2. 路由到 project（见 routing.md）
    ├─ 3. 定位/创建 tables 文档
    ├─ 4. 按模板补全缺失章节
    ├─ 5. 级联更新（血缘/指标/配置/SQL preset）
    └─ 6. CHANGELOG + 回复记录位置
```

### Step 1 — 文件路径

| 内容 | 写入位置 |
|------|----------|
| 表定义 | `{KNOWLEDGE_ROOT}/{project}/tables/{全限定表名}.md` |
| 指标口径 | `{project}/indicators/{metric_slug}.md` |
| 可复用 SQL | `{project}/sql_presets/{name}.sql` |
| 分析 SOP | `{project}/analysis_playbooks/{name}.md` |
| 产品/默认表 | `{project}/product/project_config.md` |
| 血缘 | `{project}/lineage/lineage.md` |
| 跨项目表 | `1company/tables/cross_product_tables.md` |
| 全局 SQL 红线 | `0global/sql_standards/`（仅跨项目通用规则） |
| 变更日志 | `CHANGELOG.md` 顶部追加一行 |

**文件名**：优先 `aidata2025.ods.orders.md` 这种全限定名；旧文档若已存在短名（如 `dwd_oper_user_collartweb_di.md`），**改原文件**，不要 duplicate。

**Fashion 子项目目录名**：`collart_ fashion/`（含空格，PATHS 未单独列出但 CHANGELOG 已用 `collart_fashion` 指代）。

### Step 2 — 写表文档（默认模板）

已有完整文档 → **增量追加**，不重写全文。新建或严重缺失 → 用 [table-template.md](table-template.md)。

**最少必须补齐**（用户口述什么就写什么，其余标「待补充」）：

1. **§1 基础信息**：中文名、表类型、行粒度、分区、更新频率、上游
2. **§2 核心作用**：1–3 条使用场景（用户原话优先）
3. **§3 核心字段**：仅写用户提到或分析必需的字段
4. **§4 口径/红线**（若有）：过滤条件、枚举取值、与埋点/其他表的关系
5. **§6 数据质量**：常见误用、单位、时区
6. **§7 示例 SQL**（可选）：仅当用户给了 SQL 或口径足够明确

**口述 → 章节映射**：

| 用户说什么 | 写到哪里 |
|-----------|----------|
| 「这是 XX 表 / 用来算 YY」 | §1 中文名 + §2 核心作用 |
| 「一行是一个订单/用户/天」 | §1 行粒度 |
| 「每天 8 点更新 / T+1」 | §1 更新频率 |
| 「从 A 表来的 / 服务端写入」 | §1 上游来源 |
| 「字段 X 表示… / 注意 Y」 | §3 对应字段 + §6 若属误用风险 |
| 「必须加 where … / 只有 active 算付费」 | §4 口径红线（加日期注释） |
| 「和 orders 用 user_id 关联」 | §7 或 `lineage/lineage.md` |
| 「这是默认查的表」 | `product/project_config.md` 默认表区 |

### Step 3 — 级联更新（按需，不要过度）

| 条件 | 同步更新 |
|------|----------|
| 新增 JOIN / 上下游 | `{project}/lineage/lineage.md` 表间关联表 |
| 影响 DAU/新用户/付费等定义 | `{project}/indicators/` + `indicators/README.md` 索引行 |
| 成为项目常用入口表 | `{project}/product/project_config.md` |
| 跨产品同一张物理表 | `1company/tables/cross_product_tables.md` + 各项目 tables 可短链引用 |
| 口径可复用 | `{project}/sql_presets/` + 在表文档 §7 或指标文档交叉链接 |
| 全局级红线（如 events 30 天） | 仅引用 `MEMORY-CORE.md` / `sql_standards/`，不重复发明 |

**指标 vs 表**：表文档写「这张表有什么字段、怎么过滤」；指标文档写「业务指标怎么算、推荐哪张表、口径冲突时选谁」。用户说的是「怎么算新用户」→ 优先 `indicators/`；说的是「这张表存什么」→ `tables/`。

### Step 4 — 收尾

1. `CHANGELOG.md` 顶部追加：`[{agent名}] YYYY-MM-DD — {project}：{一句话摘要}`（agent 名：cursor / codex / openclaw）
2. 回复用户（铁律，见 `AGENTS-SHARED.md`）：

```text
记住了！记录到：`{相对 ai-knowledge 根的路径}` 第 X–Y 行
（若有级联）同步更新了：`{其他路径}`
```

3. 若改动 `SOUL.md` / `USER.md` / `MEMORY-CORE.md` / `AGENTS-SHARED.md`：**先请示**，并 `.bak` 备份

## 快速示例

### 示例 A — 用户口述表用途

**用户**：`aidata2025.ads_collart.ads_oper_user_new_collartweb_di` 是 web 每日新增用户，和 dwd 那张差不多，只是 is_new=true。

**动作**：

1. 路由 → `collart_web`（表名含 `collartweb`）
2. 打开/创建 `collart_web/tables/aidata2025.ads_collart.ads_oper_user_new_collartweb_di.md`
3. §1 上游写 `dwd_oper_user_collartweb_di` + `is_new=true`；§2 写新增/渠道/设备分析
4. §6 链到 `indicators/new_user_pseudo_id.md`（若口径有冲突）
5. CHANGELOG + 告知行号

### 示例 B — 用户口述字段红线

**用户**：查 orders 算付费一定要 `status in ('active','paid','active_ending')`。

**动作**：

1. 打开 `collart_web/tables/aidata2025.ods.orders.md`
2. 追加/强化 §4，含 SQL 片段与 pending 误用说明
3. 若影响转化指标 → 检查 `indicators/conversion.md` 交叉引用
4. CHANGELOG：`固化 ods.orders 付费成功口径`

### 示例 C — 跨项目收入表

**用户**：`pubdata2025.dwd.dwd_cdct_revenue_stripe_di` 里有 android 和 web，要用 product_id 过滤。

**动作**：

1. 主文档 → `1company/tables/cross_product_tables.md`
2. `collart_web/tables/` 可保留短链说明 + 过滤示例
3. 不在 collart_web 写完整 duplicate 字段字典

## 质量自检

- [ ] 业务知识落在 `{project}/` 子目录，未散落根目录
- [ ] 表名、项目过滤与 `MEMORY-CORE.md` 一致（Web: `app_info.id IS NULL`；Android: `package_name`）
- [ ] 新口径与旧文档冲突时：**标注生效日期**，写清「推荐 vs 历史」
- [ ] 未复制 `_generated/` 全文到项目目录；只迁移用户确认的有效信息
- [ ] 回复含「记住了」+ 精确路径 + 行号
