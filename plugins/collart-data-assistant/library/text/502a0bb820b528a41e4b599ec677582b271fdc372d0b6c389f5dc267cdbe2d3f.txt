# 原始埋点与事件表

经营指标优先用新 ADS；本文说明 **何时下钻原始埋点**、四端 GA4/`events_*` 位置、DWD/DM 血缘、核心字段与关键事件。

## 何时用哪一层

| 场景 | 用哪张 |
|------|--------|
| DAU/DNU/留存/订阅/收入/渠道国家 | ADS 指标表（见 [table-routing.md](table-routing.md)） |
| 已配置热漏斗（首页/生成/保存等） | ADS `event_metric_*` / daily 事件 STRUCT |
| **新事件探查、参数明细、未进 ADS 的埋点** | GA4 `events_*` 或 DWD 事件表 |
| 用户×日语义宽表 / 归因已加工 | DM `dm_collart_*_user_event_di` |
| ASA keyword/campaign 生命周期（iOS） | 优先 active/profile；缺参再扫 GA4 finalized |

```
GA4 events_*  ──►  DWD dwd_oper_user_event(_params/_properties)_di
                         │
                         ▼
                   DM dm_collart_*_user_event_di
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       active      user_event_metric   profile
                         │
                         ▼
              event_metric_attr / country → daily
```

**原则**：能 ADS 就不扫 `events_*`；扫 `events_*` 必须守红线（见下）。

## 四端原始埋点表（GA4）

| 端 | 全限定名 | 过滤 | 备注 |
|----|----------|------|------|
| Android | `storytemplate-10a27.analytics_232977577.events_*` | `app_info.id = 'free.ai.photo.generator.collart.ai'` | 与 Web **同表**，靠 app_info 区分 |
| Web | 同上 | `app_info.id IS NULL` | 主站 |
| Fashion | 同上 | `app_info.id IS NULL` **且** `page_location` 含 studio/fashion；或加工后 `package_name='collart_fashion'` | 与 Web 共用 GA4 |
| iOS | `vidart-8b8ca.analytics_528583115.events_*` | bundle = `ai.photo.video.generator.fotos.ai.image.picture.editor.app.free`；排除 `app_info.install_source = 'manual_install'`、debug 包 | **不在 storytemplate**；导出自约 2026-05-29 |

表名模式：`events_YYYYMMDD`；当日实时：`events_intraday_YYYYMMDD`（未 finalize，勿当正式数）。

## 查询红线（events_*）

| 规则 | 说明 |
|------|------|
| 分区 | **必须** `_TABLE_SUFFIX BETWEEN 'YYYYMMDD' AND 'YYYYMMDD'`；禁止只用 `event_date` 过滤；禁止 `>=`（会扫到 `intraday_*`） |
| 跨度 | 单次 ≤ **30 天** |
| 端过滤 | Android / Web / Fashion / iOS 按上表过滤，勿混端 |
| 参数提取 | 先判断字段在顶层还是 `event_params`/`user_properties`；单 key 用标量子查询，勿无脑全量 UNNEST |
| 粒度 | 一行=一次事件；UNNEST 会膨胀行数 |
| 凭证 | 默认 `aidata2025` 可跨读 storytemplate / vidart |

正确骨架：

```sql
SELECT
  PARSE_DATE('%Y%m%d', event_date) AS event_date,
  event_name,
  COUNT(*) AS pv,
  COUNT(DISTINCT user_pseudo_id) AS uv
FROM `storytemplate-10a27.analytics_232977577.events_*`
WHERE _TABLE_SUFFIX BETWEEN '20260801' AND '20260807'
  AND app_info.id = 'free.ai.photo.generator.collart.ai'  -- Android；Web 改 IS NULL
GROUP BY 1, 2
ORDER BY pv DESC
```

取单个参数（推荐标量子查询）：

```sql
(
  SELECT ep.value.string_value
  FROM UNNEST(event_params) ep
  WHERE ep.key = 'service_type'
  LIMIT 1
) AS service_type
```

## DWD / 参数 / 属性（加工前中间层）

| 表 | 用途 |
|----|------|
| `aidata2025.dwd.dwd_oper_user_event_di` | 跨产品事件轻汇总：已扁平 `package_name`/`event_name`/`user_pseudo_id`/`country` 等，成本仍高；按 `package_name` 滤端 |
| `aidata2025.dwd.dwd_oper_user_event_params_di` | 事件参数明细 |
| `aidata2025.dwd.dwd_oper_user_properties_di` | 用户属性；iOS VidArt 自 **2026-07-26** 才有较全数据 |

Android/iOS DM 上游主要读这三张；Web/Fashion DM 直接扫 GA4 `events_*`。

端过滤示例（DWD）：

| 端 | `package_name` |
|----|----------------|
| Android | `free.ai.photo.generator.collart.ai` |
| iOS | `ai.photo.video.generator.fotos.ai.image.picture.editor.app.free` |
| Web | `collart_web`（旧表可能是 `collartweb`） |
| Fashion | `collart_fashion` |

## DM（事件语义层）

| 端 | 表 |
|----|----|
| Android | `aidata2025.dm.dm_collart_android_user_event_di` |
| iOS | `aidata2025.dm.dm_collart_ios_user_event_di` |
| Web+Fashion | `aidata2025.dm.dm_collart_web_user_event_di`（共用，靠 package 分流） |

DM 已摊平常用参数、归因、VIP 等，是 active / event_metric 的上游。需要「用户×日事件语义」优先读 DM，不要重复从 GA4 抽。

## ADS 事件指标层（热漏斗）

| 表 | 粒度 | 形态 |
|----|------|------|
| `ads_oper_user_event_metric_di` | 用户×日 | 热指标 `*_pv`（稀疏，无命中不出行） |
| `ads_oper_event_metric_attr_di` | 日×默认维 | `STRUCT<uv,pv>` |
| `ads_oper_event_metric_country_di` | 日×国家 | 上卷 → daily |
| `ads_dim_metric_rule` / Sheet | 规则 | `event_name` + `event_params`；`is_materialized` 决定是否进热列 |

热指标清单以 Sheet / `ads_dim_metric_rule` 为准。改 Sheet 不会自动改宽表，需 `collart-event-metric-sync`。

**ADS 没有的指标**：先 `SELECT aidata2025.ads_collart.ads_dim_metric_rule` 并按 `app_name` 过滤。`is_materialized=TRUE` 却缺列 → 跑 `collart-event-metric-sync`。`FALSE` → Android `CALL sp_query_event_metric_by_tag`，或按 `event_name`/`event_params`/`agg_type` 扫 DM（Android/iOS `params_info`，Web/Fashion `web_params_info`）。规则也没有再短窗扫 `events_*`。

### Android 热漏斗 ↔ 埋点（节选）

| ADS 列 | 埋点条件（示意） |
|--------|------------------|
| `home_show` | `Home_show` |
| `home_template_click` | `Home_Template_Click` |
| `album_show` | `album_show` |
| `generate_ready` | `generate_watch_ad` / `generate_pro_create` |
| `generate_save` | `ai_service_download_start` |
| `generate_start` / `generate_success` | `ai_service_start` / `ai_service_success`（按 `task_id` 去重） |
| `video_*` / `img2img_*` / `text2image_*` 等 | `ai_service_*` + `service_type` / `function_type` |

Web/Fashion daily 上常见：`page_view`、`session_start`、`first_visit`、`generate_start`/`success`、Fashion 的 `welcome_show` / `inspiration_template_show` / `video_generate_click` 等。

## 核心字段（GA4）

| 字段 | 说明 |
|------|------|
| `event_date` | STRING `YYYYMMDD`；分析日期，**不能替代** `_TABLE_SUFFIX` |
| `event_timestamp` | 微秒；`TIMESTAMP_MICROS(...)` |
| `event_name` | 事件名；不同事件参数集合不同 |
| `event_params` | REPEATED RECORD；按 key 取 `string_value`/`int_value`/`float_value`/`double_value` |
| `user_pseudo_id` | 匿名用户；主分析 ID；未登录可能变化 |
| `user_id` | 登录后业务 ID；关联 Stripe / id_map 用它。不要再关联 `ods.orders` 算收入 |
| `user_properties` | 用户属性容器；按 key 提取 |
| `app_info.id` | 包名 / Web 为 NULL |
| `geo` / `device` / `traffic_source` | 地理、设备、流量；Web campaign 优先从 `page_location` 的 utm 解析，勿只用 `traffic_source.name` |

## 关键事件速查

### 通用 / 生命周期

| 事件 | 端 | 用途 |
|------|-----|------|
| `first_open` | Android/iOS | 新增判定 |
| `first_visit` | Web/Fashion | 新增判定 |
| `session_start` | 多端 | 会话；**不算官方 DAU**（用 ADS） |
| `page_view` | Web/Fashion | PV；Fashion 含欢迎页 |

### Android（节选）

| 模块 | 事件 |
|------|------|
| 首页 | `Home_show`、`Home_Template_Show`、`Home_Template_Click`、`home_feature_click` |
| 生成准备 | `generate_watch_ad`、`generate_pro_create` |
| AI 服务 | `ai_service_task_create`、`ai_service_start`/`success`/`failed`、upload/submit/query 链路 |
| 结果 | `ai_service_result_show`、`ai_service_download_*` |
| VIP | `Subscription_Page_Show`、`vip_subscribe`、`vip_subscribe_succeed`（埋点成功 ≠ 订单成功） |
| 开屏 | `First_Page_Animation_*`、`Second_Page_Animation_*` |

### Web（节选）

| 模块 | 事件 |
|------|------|
| 页面 | `page_view`、`first_visit` |
| 生成点击 | `img2video_generate_click`、`text2video_generate_click`、`img2img_generate_click`、`text2img_generate_click` 等 |
| AI 服务漏斗 | `ai_service_start` → upload → execute → `ai_service_success`/`failed` |
| VIP | `vip_show` → `vip_subscribe` → `vip_subscribe_succeed` |

典型漏斗：

```
*_generate_click → ai_service_start → upload_* → execute_* → ai_service_success
点数用完 → vip_show → vip_subscribe → vip_subscribe_succeed
```

### Fashion（专属 + 复用）

| 模块 | 事件 |
|------|------|
| 欢迎/灵感 | `fashion_welcome_page_show`、`fashion_inspiration_*` |
| Generator | `fashion_generator_show`、`fashion_model_*`、`fashion_outfit_*`、`fashion_video_generate_click` |
| AI Model | `fashion_ai_model_*` |
| 复用 Web | `page_view`、`ai_service_*`（`service_type` 增 `fashion_video`/`ai_model`）、`vip_*`（`from` 增 `fashion_video`） |

漏斗：欢迎页 → Inspirations → Step1 模特 → Step2 服装 → Step3 Generate → AI 服务 → VIP/下载。

### iOS

- 生命周期：`first_open`；内测过滤见上表。
- ASA：`user_properties` campaignID/keywordID、`firebase_campaign`、`traffic_source`（Apple）；优先读已写入 DM/active 的字段。
- AI/VIP：与 Android 类似的 `ai_service_*` / 订阅事件族（以 GA4 实际抽样为准）。

## 分析建议

1. **业务报表** → ADS；不要用 `events_*` 现算 DAU/收入。
2. **漏斗已在热指标** → `event_metric_*`；算占比时分母用 active。
3. **新埋点 / 参数探查** → 先对 `events_*` 做短窗 `GROUP BY event_name`，再抽参数。
4. **埋点订阅成功 ≠ 服务端付费** → 见 [revenue-subscription.md](revenue-subscription.md)。
5. **Web 内部用户** → 能关联 `user_id` 时排除（[internal-users.md](internal-users.md)）。
