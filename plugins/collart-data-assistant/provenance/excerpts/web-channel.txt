# Collart Web 渠道归因

## 两层字段

- `traffic_src_type`：渠道性质，主要取值为 `delivery` / `nature` / `inhouse` / `kol`。
- `traffic_src_platform`：具体投放平台，如 `ga_delivery` / `fb_delivery` / `x_delivery` / `tt_delivery`。Instagram 属于 Meta，IG campaign / source=ig|instagram 一律 `fb_delivery`，不再单列 `ig_delivery`。
- **Web 统计只认 `x_delivery`**：历史短名 `x` / `X` 视为同义旧值，DM / active / profile 写入时归一，不单独成桶。不改 iOS（iOS 投放平台仍是短名 `x`）。
- Web / Fashion 画像 `ads_oper_user_profile_df.page_referrer`：最早 `first_visit` 的**完整**上一跳 URL（空串=当时无 referrer；无 first_visit 则最早事件）。只写一次，常规分析直接用画像，不必再扫 `events_*`。

## X / 付费 TT 规则

生效日期：2026-09-05（旧值 `X` / `x` 已统一为 `x_delivery`）。2026-09-10：日表已无短名；画像 `ads_oper_user_profile_df` 残留 `x` 一次性改名为 `x_delivery`。

- `sptt-` / `tt_official` / `tt_*` / `youtube_*` / `^kol` 保持 **kol**，不是 `tt_delivery`。
- 付费 X：落地页 `utm_source=X`，或 source∈{x,twitter}，或 campaign `CW_X_` / `X-` → `x_delivery`。
- 付费 TikTok：source 含 tiktok/bytedance，落地页 `utm_source=tiktok`，或 campaign `TT-` / `TIKTOK` → `tt_delivery`。
- AppLovin：`source` 含 applovin → `applovin_delivery`。
- 同一用户日只要出现过 X 落地页，active 优先 `x_delivery`。
- **Web FB 保持现网口径**（2026-09-06 确认）：Firebase `traffic_source` + 落地页付费 `utm_medium` / FB campaign；**不要**改成「traffic_source.name + page_location.utm_source + user_properties.utm_source」三源拼 FB；**不要**把 facebook.com / m.facebook.com referral 升成投放。近 10 日对账：付费 FB 与三源重合，差额几乎全是自然跳转。

## 血缘

`dm.dm_collart_web_user_event_di` 写出 `traffic_src_type` + `traffic_src_platform`，
`ads_collartweb.ads_oper_user_active_di` 优先沿用 DM platform（缺省再推导），并传递到：

- `ads_oper_user_profile_df.traffic_src.platform`
- `ads_oper_basic_indicator_attr_di.traffic_src_platform`
- `ads_oper_event_metric_attr_di.traffic_src_platform`

country / daily **没有 platform 维**，只把 X 并进 `dnu_by_source.delivery`。2026-08-25 核对：8/17–8/24 attr/country/daily 的 organic、delivery 已对齐，不必再为 X 单独回补 country/daily。

首次回补范围：2026-08-17 至 2026-08-23（DM / active / attr / emat / profile）。country/daily 随 2026-08-25 的 purchase 回补一并刷到 8/24。
