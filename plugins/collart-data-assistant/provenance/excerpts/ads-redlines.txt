# Collart ADS 现网红线（2026-09-07）

分析默认走四端新 ADS。下面是本轮已定口径，避免再踩过时文档。

## 收入

- 用户粒度：**不要** `ods.orders`。Web / Fashion / 移动端 RUB 用 `pubdata2025.dwd.dwd_cdct_revenue_stripe_di`，或各端 `ads_oper_user_active_di.revenue`。
- **不要**用 `dwd_cdct_orders_revenue_hi` 补当天（空表，0 行）。T+1 没到就等次日。
- 四端 profile 终身收入 = `SUM(active.revenue)`，不再回扫 DWS，不再 orphan 二次叠加。
- country / daily 仍读 `ads_ad_sub`；与用户粒度允许对不齐。

## 投放花费

- 只认 `aidata2025.dwd.dwd_cdct_delivery_cost_di`，或已经上卷的 `country.delivery` / `daily.delivery`。
- **不要**扫 `ods_facebook_delivery_*`、旧 `dws_oper_fb_delivery_1d`。
- ADS / cdct Web 包名：`collart_web`。ODS 的 `collart-web` 是别人的层，不是脏数据。
- Fashion country `delivery` 仍硬编码 0，专项再接。

## 映射

- Fashion 用户/订单收入：用 `ads_collartfashion.ads_oper_user_revenue_di`（订单粒度，Stripe 全字段）。不要再读停更的 `ads_collart.ads_oper_user_revenue_collart_fashion_di`。
- Web Stripe：同日 DM 末次 pseudo，否则 id_map 最近绑定（不卡首见日）。无设备的真 miss 丢掉，不硬挂。
- Web profile：一行一个 `user_pseudo_id`。`user_id` = 最后一次登录；历史登录号在 `user_ids`。按登录 UUID 查不要只扫 `profile.user_id`。
- `ads_vip_user_info_all` Web 维度走 `UNNEST(user_ids)`；active / attr / country / daily / KOL 不用改（按 pseudo）。
- profile 无 active 的骨架人付费为 0，不是漏单。
