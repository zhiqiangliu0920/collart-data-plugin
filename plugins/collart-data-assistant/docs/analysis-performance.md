# 分析效率与运行记录

默认检索先查主题，无命中再查当前全文资料。`--scope all` 同时比较两层；`--include-history` 显式扩展历史。`historical_or_unreviewed_matches=null` 表示没有为计数扫描被隐藏正文，不代表历史无匹配。别名只帮助找到口径，不确认业务事实。

主题索引由 `kb.py --root <源码> --authoring index` 构建，随版本分发。读取时比较主题正文、主题来源变更清单和路由配置的内容指纹；变化或缺索引时直接使用当前正文，返回 `index_state=live_fallback`，不写安装缓存。仅主题搜索不读取全文目录或历史正文。维护检查要求索引与源码一致；`source_pipeline` 构建后必须重新 index。

## 有界读取

`read <主题ID或来源ID>` 默认正文最多 3500 字符，状态和来源摘要另行返回。`--section '准确标题'`、`--start-line N --end-line M` 缩小范围；行号相对于返回文档的业务正文，主题不包含 frontmatter。`--offset` 是选区内的字符偏移，`next_offset` 用于相同选区继续读取。只有需要整份证据时才用 `--full`。链接和来源清单有上限，完整溯源台账仍保留。

片段不能独立覆盖整份资料的适用条件。先读取当前任务的数据访问约定和指标契约；历史资料中的旧调用不是执行授权。资料读取不触发数据库请求。

## 同事任务的测量

在当前分析项目记录下列实际数据；未提供则用 null，不用字符数估算计费 token。不要记录凭证、完整用户明细或敏感 SQL 参数。

| 项目 | 要记录的内容 |
|---|---|
| 版本与环境 | 插件版本/提交、模型/推理设置、开始/结束时间、是否新任务 |
| 知识读取 | 搜索次数、资料读取次数、返回字符数、实际耗时、是否使用历史资料 |
| 模型消耗 | 平台可提供的输入、输出、缓存 token；不可见时留空 |
| 数据库 | 元数据/dry-run/query 次数；job ID、排队/执行时间、扫描字节、缓存命中 |
| 返工 | 原因：连接、SQL、口径不清、无数据、索引未命中、输出乱码；同一 job 不重复提交 |

`scripts/benchmark_retrieval.py --plugin-root <插件路径> --output <当前项目中的JSON文件>` 只测本地检索和有界读取，不访问数据库。每个方案预热一次，再交替测量。输出中位数和原始样本、字符数、主题 ID。该测试只能说明检索环节变化，不能代表完整分析的 token 或总耗时。

首批回归问题包括 Android 收入、免费看广告按钮、复合问题、Web 收入、精确表名、公司规则和未知词。验收同时检查召回与状态边界，不为提速去掉 schema、新鲜度、只读或原始事件最近 30 天检查。
