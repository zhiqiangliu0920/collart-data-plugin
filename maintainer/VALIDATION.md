## 固定问题基准

对比旧 0.4 快照与当前新结构。9 个固定问题：Android 收入、广告按钮点击、Web 画像登录号、Fashion 收入交集、ASA、成熟留存、ADS 回退、无连接、Web 用户价值分层。每题顺序运行默认 search，再按已知正确 ID read，重复 3 次；每题取耗时中位数再汇总。

| 测量 | 0.4 | 0.5 |
|---|---:|---:|
| 返回字符数 | 43,010 | 25,964 |
| CLI 调用数 | 18 | 18 |
| read 次数 | 9 | 9 |
| 合计耗时中位数（毫秒） | 3,292.96 | 3,351.21 |

输出字符数下降 **39.63%**。本次耗时约增加 1.8%，没有证明速度提升；进程启动、本地文件校验及磁盘状态均影响结果。新增精确字段/章节读取另有测试，不计为这组基准的额外节省。

这是可重复的 CLI 对比，read 目标 ID 预先已知，不是完整自主分析评测。未调用模型，因此没有真实 usage，**不把字符降幅当作 token 降幅**。原始逐题记录见 [benchmark.json](benchmark.json)。

## 复现与稳定构建

在仓库根目录使用 Python 3.10+；构建和检索仅需标准库。

```text
python -B -X utf8 scripts/build.py
python -B -X utf8 -m unittest discover -s tests -v
python -B -X utf8 scripts/build.py --check
python -B -X utf8 scripts/benchmark.py --before <0.4插件目录> --output <基准结果.json>
```

`build.py` 仅从当前规范正文生成索引及发行 hash 清单。重复构建必须得到相同文件；后续变更应先重建，再运行 `--check`，不能通过删除未知字段来让检查通过。发行清单见 [release-files.json](release-files.json)，除清单自身外，每个发行文件均有 hash。
